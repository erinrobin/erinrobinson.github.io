Background

Curious by default, structured by training

Computer Science gave me the tools, training gave me the structure. During late nights, I bring ideas to life through hands-on building and tinkering. That has lead me to build and figuring many things that lecture rooms couldn't teach.

Give me a weekend and I'll usually find something to build — a Pac-Man clone from scratch, a script pulling apart pulsar signal data just to see what's in it. I like the version of computer science where you get to make something concrete, then poke at it until it breaks, then work out why.

What it is

Built in the CBL course in Q4 of my first year, YieldWise is an autonomous system for monitoring pests in the field, built with a team of six on ROS. The brief was framed around UN SDG 2.3 — raising the productivity and incomes of small-scale food producers — so the system was designed to catch pest damage early enough for a farmer to actually act on it. My contribution centred on the layer where people meet the system, and on proving it behaves when things break.

What I did

  • Helped develop a live web dashboard for monitoring and fault injection, so the system's state is readable rather than inferred.
  • Validated the system through structured fault-tolerance testing: deliberately breaking things and documenting exactly how it degraded.
  • Organised and communicated a multi-part technical effort across six people, keeping the moving parts explainable.

What it is

A Pac-Man clone built from scratch in Java with a teammate, for a first-quarter assignment. GameWindow.java opens the window and drives the game loop; it calls into Pacman.java for the core logic. Both files and all image assets need to sit in the same folder to run.

What I built

  • Pac-Man and ghost movement, with collision handling around the maze walls.
  • Score tracking from eating dots and cherries — cherries only spawn in Maze 3.
  • Teleport portals, a lives system, and multiple selectable levels and mazes.
  • Full game flow: start screen → level select → maze select → play. Losing resets to the same choices; winning returns to level select.

Maze 4 is a stripped-down test maze, built to check the winning case quickly, so a few features are deliberately left out of it.

The problem

A lot of what makes healthcare hard to access isn't the medicine — it's the admin. Built with two other students in high school, this is a Python program backed by a SQL database that keeps doctors, patients and admin staff organised in one place, so booking, cancelling and looking up a patient's details doesn't depend on someone finding the right folder.

What I did

  • Designed the SQL schema for doctors, patients, admins and appointments, and wrote the Python logic that reads and writes to it.
  • Built the booking and cancelling flow, so an appointment could be created against a specific doctor's schedule and pulled back up on request.
  • Structured patient records so details could be found and updated quickly by admin staff.
